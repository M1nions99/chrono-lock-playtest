## 게임의 한 문장

붕괴 중인 우주정거장의 시간 실험 연구소에서, 장치의 시간을 멈추고 가속하고 되감아 탈출하는 빠른 템포의 1인칭 3D 퍼즐 게임.

가제는 CHRONO / LOCK. 이름의 상표나 배포 가능성을 확인한 것은 아니므로 출시 전에 별도 검토한다.

초기 가정은 Windows PC, 키보드·마우스, 싱글 플레이, 현실적인 중력이다. 핵심 목표는 이동의 경쾌함, 한눈에 읽히는 장치, 짧은 재시도다. Portal의 공간 퍼즐 학습 구조와 연구 시설 분위기를 참고하되 포탈 장치, 캐릭터, 대사, 음악, 상징 디자인은 독자적으로 만든다.

## 플레이 감각

- 관찰 5~10초 → 조작 2~10초 → 이동 → 즉시 결과 확인의 짧은 반복.
- 실패 시 마지막 안전 지점으로 복귀. 기본 모드에는 강제 시간 초과를 두지 않는다.
- 조작 가능한 장치는 색과 이름, HUD 진행도로 구분한다. 색만으로 규칙을 전달하지 않는다.
- 먼저 한 가지 능력을 배우고, 다음 방에서 기존 능력과 새 능력을 조합한다.
- 이동 속도 초안: 걷기 4.5m/s, 달리기 7m/s. 마우스 시점, 낮은 점프, 기본 시야각 80도.

## 시간 규칙

| 능력 | 기본 효과 | 첫 사용 | 제한 |
|---|---|---|---|
| 정지 | 선택 장치의 상태 변화 정지 | 회전 위험 구역 통과 | 플레이어와 다른 장치는 계속 움직임 |
| 가속 | 선택 장치의 정상 변화 속도 4배 | 발전기 충전 | 정상 충전도 가능, 효율적으로 해결하는 능력 |
| 되감기 | 기록된 장치 상태를 2배속으로 복구 | 사고로 내려간 연결 다리 복원 | 최대 약 8초 기록, 기록 이전으로 이동 불가 |

현재 시제품은 **한 번에 한 장치**에 효과를 유지한다. 새 장치에 적용하면 이전 장치는 정상화된다. 효과는 조준을 풀어도 유지되며 우클릭으로 해제한다. 사거리는 적용 시 9m다. 벽을 통과해 선택할 수 없다.

장치 완료 후 E로 확정하면 안전 잠금이 걸린다. 잠긴 장치는 시간 조작에 영향을 받지 않는다. 회전 구역은 통과 직후 자동 잠금된다. 이 규칙으로 앞서 풀었던 구역이 다시 막히는 상황을 방지한다.

되감기 범위는 **장치의 내부 진행 상태**다. 플레이어 위치, 목표 완료, 문, 전체 물리 세계, 경과 시간은 되돌리지 않는다. 자유로운 Rigidbody 물리 되감기는 후속 연구 항목이다. 다리에는 입장 전 4초 동안 발생한 붕괴 기록이 미리 입력되어 있다. 발전기는 실제 플레이 중 축적된 충전 기록을 되감는다.

## 첫 시제품 동선

약 12m × 52m의 선형 연구 구역. 최초 플레이 2~4분을 목표로 하되 실제 소요 시간은 플레이테스트 후 조정한다.

```text
입구 z=3
  ↓ 이동 / 시점 익히기
로터 z=10       [1 → 좌클릭 → 통과] 안전 체크포인트
  ↓
발전기 z=22     [2 → 좌클릭 → 충전 100% → E]
전력 문 z=27
  ↓
다리 제어기 z=30 [3 → 좌클릭 → 복구 100% → E]
붕괴 구간 z=32~38
  ↓
에어록 z=48     [접근 → E] 결과 / 재시작
```

로터의 날개는 표시용이며 위험 여부는 회전 구역 전체에 대한 통과 판정으로 처리한다. 정지 시 날개에 걸리는 문제를 줄이기 위한 초기 구현이다. 후속 단계에서 실제 움직이는 장애물 퍼즐로 교체할 수 있다.

## 이후의 게임 구성안

| 구역 | 학습 / 조합 | 완성 기준 |
|---|---|---|
| 01 각성 연구실 | 정지 / 가속 / 되감기 각각 학습 | 외부 설명 없이 튜토리얼 완료 |
| 02 동력 제어실 | 가속으로 타이밍을 만들고 정지로 유지 | 장치 두 개의 인과관계가 읽힘 |
| 03 사고 기록실 | 움직였던 물체의 과거 경로 복원 | 되감기 한계와 경로를 시각화 |
| 04 정거장 외곽 | 이동하며 능력 전환, 체크포인트 | 반복 실패에도 조작 스트레스가 낮음 |
| 05 비상 에어록 | 세 능력을 짧은 연속 퍼즐로 조합 | 배운 규칙만으로 마지막 탈출 가능 |

이는 후속 기획이며 현재 구현된 다섯 방이 아니다. 첫 공개 데모는 10~15분 목표의 2~3개 구역부터 시작한다. 최종 플레이 시간과 방 수는 실제 제작 속도에 맞춰 확정한다.

## 구현 구조

| 파일 / 구성 | 책임 |
|---|---|
| ChronoPlayer | CharacterController 이동, 시점, 입력 전달 |
| TemporalDevice | 장치 상태, 제한된 이력, 정지·가속·되감기 |
| ChronoGame | 목표 순서, 조준, 적용 대상, 체크포인트, HUD, 성공 / 재시작 |
| ChronoLabBuilder | 편집 가능한 테스트 장면·재질 생성, 로직 검증 |

시제품은 단순성을 위해 장치 종류별 분기를 사용한다. 서로 다른 퍼즐이 4종 이상 늘어날 때 `ITemporalTarget`, 장치별 상태 스냅샷, 목표 이벤트, 프리팹으로 분리한다. 지금부터 복잡한 범용 프레임워크를 먼저 만들 필요는 없다.

후속 구현 우선순위는 입력 재매핑 / 감도와 시야각 설정, 조작 대상 외곽선, 사운드 피드백, 프리팹화, 저장, 접근성, 물리 되감기 순이다. 출시용 UI와 오디오는 현재 시제품에 포함되지 않는다.

## Blender 제작 사양

원본 `.blend`는 `ArtSource/Blender`, Unity용 모델은 `Assets/ChronoLock/Art`에서 관리한다. Steam 설치 Blender 5.2.1과 실제 Blender MCP 연결을 사용해 모듈·블랙홀 타이틀 배경·구조 침상·손바닥 앵커를 제작했다. 최신 검증 범위는 `시작연출_변경과_검증.md`, 연결 기록은 `Blender_MCP_연결상태.md`에 기록했다.

- 1 Unity 유닛 = 1m. Blender Metric, Unit Scale 1.0.
- 모듈은 1m 격자 기준. 바닥 4×4m, 벽 4×3m, 출입구 유효 폭 2m 이상 / 높이 2.4m 이상.
- 회전 / 스케일 적용 후 FBX 내보내기. 최초 테스트 큐브를 가져와 Unity에서 실제 1m인지 확인한다.
- 회전 장치는 회전축에 피벗, 바닥과 벽은 조립 기준점에 피벗. 움직이는 부품과 외함을 별도 오브젝트로 분리.
- 충돌은 단순 BoxCollider 우선. 작은 장식에는 충돌을 붙이지 않는다.
- 공통 금속 / 세라믹 / 고무 / 발광 재질을 재사용. 주요 장치에만 고유 텍스처.
- 초기 목표: 일반 모듈 0.5k~3k 삼각형, 핵심 장치 3k~10k, 1~2K 텍스처. 성능 측정 후 조정하는 예산이다.

첫 에셋 순서: 바닥 → 벽 → 문틀 → 조명 → 콘솔 → 로터 → 발전기 → 다리 → 에어록. 최소 모듈로 한 방을 완성한 뒤 변형을 만든다.

## 작업 분담

- **이 작업의 설계 / 통합 담당:** 규칙 설계, 퍼즐 순서, Unity 구조, 구현 통합, 검증과 수정.
- **Claude Code에 맡길 수 있는 독립 작업:** 오디오 서비스, 설정 메뉴, 장치 외곽선 중 하나. 아래 인계 문서로 파일 범위를 제한해 전달한다. 현재 Claude Code를 실제 호출한 것은 아니다.
- **Blender 작업:** 모듈 제작과 피벗 / 크기 검증, 장치 모델 교체. 제공된 생성 스크립트는 출발점이며 최종 아트가 아니다.
- **사용자 판단:** 게임 감각 확인, 퍼즐 난이도 / 아트 방향 선택, 플레이테스트 피드백.

두 코드 도구가 같은 파일을 동시에 수정하지 않도록 한 작업 단위마다 담당 파일을 정한다. Git을 도입할 때 Unity의 Assets / Packages / ProjectSettings와 `.meta`를 관리하고 Library / Temp / Logs / Obj / UserSettings / Builds는 제외한다. Blender 원본 같은 큰 바이너리는 Git LFS 후보로 둔다. 기존 저장소 설정은 이 작업에서 자동 변경하지 않는다.

## 제작 단계와 통과 조건

1. **현재: 기술 시제품.** 이동, 세 능력, 목표 순서, 탈출, 재시작. 로직 검증과 사람이 직접 하는 조작 검증을 구분한다.
2. **다음: 첫 방 재미 검증.** 3명 이상에게 설명 없이 제공해 첫 능력을 이해하는 시간과 막힌 지점을 기록한다. 해결책을 말해줘야 했던 부분부터 수정한다.
3. **첫 방 아트 교체.** Blender 모듈, 조명, 장치별 효과음, UI를 적용. 모델 교체 후 통로 폭 / 충돌 / 시야를 재검증한다.
4. **세로 완성 데모.** 2~3구역, 시작·완료 화면, 감도·볼륨 설정, Windows 배포 빌드. 목표 PC에서 1080p 60fps를 측정한다.
5. **콘텐츠 확장.** 검증된 규칙으로 추가 구역 제작. 저장·현지화·사운드·최적화·배포 준비.

일정은 팀 인원, 주당 작업 시간, 모델링 숙련도, 목표 PC를 확인한 뒤 산정한다. ‘며칠이면 완제품’ 같은 확정 일정은 두지 않는다.

## 수동 플레이 확인표

- 장면 실행 시 카메라가 정상이며 마우스 / WASD로 움직이는가?
- 정지하지 않고 로터에 접근하면 안전 지점으로 복귀하는가?
- 로터를 정지하면 통과하고 목표가 갱신되는가?
- 새 대상에 능력을 적용하면 이전 대상 효과가 해제되는가?
- 발전기 100% 상태에서 조준 후 E를 눌러 문을 여는가?
- 벽 너머 또는 9m 밖의 장치를 선택할 수 없는가?
- 다리가 복원되고 확정 후 안전하게 건널 수 있는가?
- 추락 후 재도전과 세 능력 재사용이 가능한가?
- Esc 중 장치와 경과 시간이 멈추고 복귀하는가?
- E로 탈출한 뒤 R 또는 버튼으로 초기 상태부터 다시 진행되는가?
- Game 뷰 크기가 달라도 HUD가 잘리지 않는가?
