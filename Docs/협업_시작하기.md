# CHRONO STATION — 협업 시작하기

새로 합류한 사람이 처음 한 번만 하면 되는 세팅입니다.

## 1. 필요한 것

| 항목 | 버전 | 비고 |
|---|---|---|
| Unity | **6000.3.23f1** | 버전이 다르면 씬·프리팹이 깨집니다. 반드시 동일하게 |
| Git | 2.30 이상 | https://git-scm.com/download/win |

Unity는 Unity Hub → Installs → Install Editor → Archive에서 `6000.3.23f1`을 정확히 골라 설치하세요.

## 2. 받아오기

```
git clone https://github.com/M1nions99/chrono-lock-playtest.git
```

받은 폴더를 Unity Hub에서 **Add → 폴더 선택**으로 열면 됩니다.
첫 실행은 `Library` 폴더를 새로 만드느라 몇 분 걸립니다. 정상입니다.

> `Library`, `Temp`, `Logs`, `UserSettings`, `.csproj`는 저장소에 없습니다.
> Unity가 알아서 만드는 파일이라 올리지 않습니다.

## 3. 씬 병합 도구 설정 (한 번만, 꼭 하세요)

이걸 안 하면 두 사람이 같은 씬을 건드렸을 때 병합이 불가능해집니다.

```
git config --global merge.unityyamlmerge.name "Unity YAML Merge"
git config --global merge.unityyamlmerge.driver "'C:/Program Files/Unity/Hub/Editor/6000.3.23f1/Editor/Data/Tools/UnityYAMLMerge.exe' merge -p %O %B %A %A"
git config --global merge.unityyamlmerge.recursive binary
```

Unity를 다른 경로에 설치했다면 위 경로만 바꿔주세요.

## 4. 평소 작업 흐름

```
git pull
```
작업 시작 전에 **항상** 먼저 받아옵니다.

```
git checkout -b 작업이름
```
기능별로 브랜치를 파고 작업합니다. `main`에 직접 올리지 않습니다.

```
git add .
git commit -m "무엇을 바꿨는지"
git push -u origin 작업이름
```

올린 뒤 GitHub에서 **Pull Request**를 만들면 상대가 확인하고 합칩니다.

## 5. 충돌을 줄이는 규칙

- **같은 씬을 동시에 만지지 않기.** 씬 파일은 병합이 제일 까다롭습니다. 누가 어느 씬을 잡는지 미리 말해두세요.
- 큰 변경일수록 자주, 작게 커밋하기.
- `.meta` 파일은 반드시 같이 커밋하기. 빠지면 상대 쪽에서 참조가 끊깁니다.
- Unity를 켠 상태로 `git pull` 하지 않기. 에디터를 닫고 받는 편이 안전합니다.

## 6. 절대 올리면 안 되는 것

`.gitignore`가 대부분 막아주지만, 혹시 모르니:

- 개인 인증 정보 (`.env`, 토큰, 비밀번호)
- `Library/`, `Temp/`, `Logs/`, `UserSettings/`
- 빌드 결과물 (`*.exe`, `*_Data/`) — 실행판은 GitHub **Releases**로 배포합니다

## 7. 실행판만 필요한 사람은

빌드할 필요 없이 [Releases](https://github.com/M1nions99/chrono-lock-playtest/releases)에서
`CHRONO_STATION-Windows.zip`을 받아 압축을 풀고 `CHRONO_STATION.exe`를 실행하면 됩니다.

## 조작

| 입력 | 동작 |
|---|---|
| 우클릭 | 자기 자신에게 시간 능력 사용 |
| 좌클릭 | 조준한 사물에 시간 능력 사용 |
| 마우스 휠 / 1~4 | 능력 선택 |
| Q | 자기·사물 효과 전체 해제 |
| WASD / Space | 이동 / 점프 |
